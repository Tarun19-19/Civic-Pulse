How the CivicPulse Sight priority engine works

Three city infrastructure datasets flow through a leakage-safe pipeline into a transparent, regularised score. Every rank ships with its reasons, a confidence label and a list of what we still don't know — rendered on the CivicPulse Sight 3D globe stack (CesiumJS).

System flow

Priority score — six transparent components

Severity-weighted incident load 0.30
Unresolved backlog / slow fixes 0.20
Public complaint pressure 0.15
Exposure: road, density, school, hospital, pedestrians 0.15
Injuries & critical events 0.10
Worsening trend (last 90 days) 0.10
Weights are expert-set, visible in the app, and meant to be tuned by officials — not fitted to noise.

Design decisions

Regularised, not overfit. Sparse locations are shrunk toward their zone mean; models use L2 / L1+L2 penalties.
Leakage-safe. Features use events before the as-of date; test targets come strictly after it. Train on earlier cutoffs, test later.
Explainable. Top-3 contributing components, the full breakdown, rank interval and "what's missing" appear for every location.
Free to run. Static JSON + CDN CesiumJS + OSM tiles. No API key, no server. Host on Vercel, Netlify, Cloudflare Pages or GitHub Pages.

Honest limits

The dataset is synthetic. Incident counts per location behave like Poisson(10) noise and are unrelated to location attributes; every model (and our score) scores about chance on a held-out quarter. We report that instead of claiming accuracy. The score is evidence triage; with real data the same pipeline would measure real lift. Coordinates are simulated and must not be read as real places.
