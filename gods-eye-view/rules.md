Ground rules
Data Science Club VIT-APIIEC
15 rules. Tap any rule to expand.

Choose one track.
Build against the corresponding problem statement and starter dataset.

The provided dataset is foundational.
You may add relevant public data, APIs or self-collected data if permitted, but you must still use the supplied dataset meaningfully.

Tell us about extra data.
If you used data beyond the provided pack, say where it came from.

No replacing the core dataset.
A product that ignores the provided data and relies entirely on an external API will lose data-use marks.

Build a product, not only a model.
A notebook, static chart or model file alone is not a complete submission.

Model claims must be supported.
Report the evaluation method and appropriate metrics. Do not claim “high accuracy” without evidence.

Prevent leakage.
Use time-based or group-based splits where appropriate; never use future information to predict the past.

Explain the result.
A user should understand why a prediction, alert or recommendation appeared.

Acknowledge synthetic-data limits.
You cannot claim the generated data proves real-world performance.

Responsible use.
No real personal/medical records, unauthorised access, unsafe live deployment or misleading public-safety claims.

Use permitted tools.
Disclose every API key, pretrained model and external service. They are allowed as supporting parts, but a model trained from scratch earns far more marks than an API-key solution.

Demonstrate the workflow.
Judges should see a real input and a useful product output.

One overall competition.
All tracks use the same judging rubric and compete for the same prizes.

Submission freeze.
Submit your source/demo and presentation by the deadline announced by the organisers.

Team integrity.
Identify borrowed code, datasets, models and templates. Plagiarism or fabricated evaluation results may lead to disqualification.
